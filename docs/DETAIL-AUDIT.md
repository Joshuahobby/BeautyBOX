# Detailed product, implementation and optional-item audit

16 November 2026 · branch `codex/beautybox-storefront-rebuild` · local production build, PostgreSQL TEST data and simulated providers.

The review found and corrected functional and presentation gaps that the earlier targeted checks missed. The complete feature/optional/deferred ledger is [SCOPE-COVERAGE.md](SCOPE-COVERAGE.md). This is not a launch approval: Google billing, external sandbox/storage access, real SMS, approved inventory/content and operational/legal inputs remain separate dependencies.

## Fresh evidence and method

Captured the actual home-to-order flow before changes, inspected saved screenshots, exercised failure states, then reviewed code and fixed confirmed issues. Final screenshots are under `evidence/detail-audit/after/`; originals before the changes are under `before/`. Image sheets are only viewing aids; the individual captures remain the evidence. Synthetic recipient/phone/order data only.

The initial 17 screens had no detected axe violations or page-width overflow. Those scans did not reveal the unusable manual-location fallback, missing destination review, lost-response interaction or the unvisited stock page's phone-width overflow. Additional scripted checks reproduce those behaviors directly. Screenshot appearance alone is not accessibility compliance, stock/money correctness or live-provider evidence.

## Optional/live checks and boundaries

- Optional Google street map: implemented/mock-tested. Server Routes and browser Embed keys are present and distinct; browser/API restrictions and real map behavior still need account-side verification. Billing remains owner-reported closed. No authenticated Google request was made.
- Optional Supabase Storage: two external tests reviewed but blocked by missing current `.env.local` URL/secret. Existing local/mock storage checks were run. No remote objects created.
- Optional pawaPay sandbox: four external tests reviewed but blocked by missing current sandbox mode/token. Existing local provider imitation and money/recovery tests were run. No external collection/refund or real payment attempted.
- Optional local backup/restore: fresh database-only rehearsal included a synthetic order and pending job. Fresh database-and-media rehearsal verified two temporary images by hash. See `database-restore.json` and `database-and-media-restore.json`. No hosted restore was performed.
- Deals, shop favourites, wishlist/reviews/recommendations, real SMS, analytics and later business-plan phases have explicit statuses in the coverage ledger. They are not silently counted as done.

`npm run audit:optional` reports readiness and prerequisites with zero requests. READY_TO_OPT_IN is not a passed live test. Full copies of keys, database dumps, staff credentials or customer data are not part of this report.

## Verification and practical limits

Fresh command results are recorded in [verification.json](evidence/detail-audit/verification.json). Tokens, pinned v1.2 contract, types/lint and 132 unit tests passed. Real-PostgreSQL integration passed 185 cases, with six optional external cases skipped. The complete Chromium run passed 58 cases; after the final recipient and mobile-card changes, focused production-build runs passed 14 purchase/audit cases, seven final audit cases and three desktop staff regressions. There are 59 distinct passing browser cases across the runs; this is not a claim of one final 59-case run.

The final 19 captured states have zero detected axe violations, broken images or page-width overflow. The before/after screenshot runs deliberately inject a search 503 and a lost response; those two controlled console errors are fault evidence, not unexplained application errors. Screen-level axe checks are supplemented by keyboard, reflow, strict CSP and functional tests; real assistive technology/device review remains a release input. See the [compact screenshot preview](evidence/detail-audit/audit-preview.png), [final observations](evidence/detail-audit/after/observations.json) and the individual screenshots above.

No main merge, deployment, cloud publication, hosted settings change, real payment or real SMS was performed. The branch remains a reviewable implementation checkpoint. Reopening billing, supplying isolated sandbox/storage credentials, implementing/configuring real notifications and providing approved launch data/operations/policies are the next external/release tasks.
