Baseline: `BeautyBOX-Handoff-v1.0/technical/API-Contract.openapi.json` (unchanged, read-only). All changes are **additive**; no supplied path, method, request field or status code was removed or changed. Runtime request schemas (`src/server/http/schemas.ts`) remain strict (unknown request fields are rejected).

Behaviour notes for I09-I11 (no shape change):

- `POST /order-access/exchange`: unknown, revoked and already-used tokens all return 404 with the same message; a genuine expired token returns 404 with the "expired" recovery message. Re-presenting a used token from a browser that already has access to that order returns 200 without issuing a new cookie.
- `POST /orders/{orderId}/cancellation-requests`: records a request (202, Operation PENDING); a repeat while one is pending returns the same operation. After handover it returns 409 `ACTION_NOT_ALLOWED` (support handles returns). Staff `CANCEL` resolves it SUCCEEDED; a winning `HAND_OVER` resolves it FAILED.
- `POST /staff/orders/{orderId}/commands`: `START_PREPARATION` is also accepted from `ON_HOLD` (resume) when payment is verified and stock fully allocated; `HOLD` sets `holdReason = MANUAL`. Responds with the updated `StaffOrder`.
- `POST /staff/orders/{orderId}/access-links` revokes all outstanding links **and** order-scoped sessions for the order, then queues an SMS with a new link to the order contact. The token never appears in the response.
- Refund callbacks (`kind: REFUND`) only re-arm the authoritative refund status check, like deposit callbacks.
- Private order sessions use one cookie per order (`bb_order_<orderId without dashes>`), so a browser can hold access to several orders (RF-25). A support reissue also ends access for the browser that placed the order (RF-22).
- `StaffOrder.recipient` for roles without contact access is the contract's `MaskedRecipient` (`+2507******12`) and `destination` is null.
- `POST /staff/media/upload-intents` returns 200 (as the contract says) and claims the Idempotency-Key; media endpoints are ADMIN/OPERATIONS for both purposes (RF-24).
- With Supabase Storage (DR-041), `MediaUploadIntent.uploadUrl` is a signed URL on the Supabase origin, bound to that upload's staging path and valid for Supabase's fixed 2 hours, rather than `PUT /staff/media/{uploadId}/content`. Clients send `PUT` with the file as the body and only a `Content-Type` header (no cookies or other headers). `PUT /staff/media/{uploadId}/content` remains for local storage. Finalize enforces the declared size on the bytes that arrived. Replaying the intent request after the upload is finished or expired answers 409 `ACTION_NOT_ALLOWED` instead of issuing a new URL.
- `MediaFinalizeResult.url` and `StaffProduct` media URLs point at the app's guarded `/media` route; the public `Product` image URLs point at the public bucket (or `NEXT_PUBLIC_MEDIA_BASE_URL`) once a photo is approved.
- `POST /staff/products/{productId}/publication` with `PUBLISHED` answers 503 `PROVIDER_UNAVAILABLE` (the documented `default` error response) when the approved photos cannot be made public; nothing is published.
- `GET /api/v1/internal/reconciliation` (worker secret) returns the reconciliation sweep (counts and record ids only); `GET /api/v1/internal/ops-summary` adds `refunds.stuckOverADay`, `refunds.amountMismatch` and `stock.ledgerDriftLots`. These internal endpoints are not part of the public contract.

Error semantics follow the supplied mapping. Implementation notes: `OUTSIDE_COVERAGE` is returned with HTTP 422; special-parcel baskets return `VALIDATION_ERROR` with `fieldErrors[].field = "parcel"`; a paused checkout or unavailable provider returns `PROVIDER_UNAVAILABLE` (503) before any intent is accepted.

Behaviour notes for suppliers and settings (no shape change):

- `POST/PATCH /staff/suppliers` are ADMIN only (FINANCE keeps read and settlement). Supplier edits never rewrite recorded obligation amounts.
- `POST /staff/supplier-obligations/{id}/settlement` returns 409 `ACTION_NOT_ALLOWED` unless the obligation is valued, unsettled, and its goods were handed over (allocation SHIPPED, order not cancelled). It records evidence only.
- `PUT /staff/settings` ignores `version`, `publicationBlocks` and `tariff.version` in the body (server-owned). A tariff or area change creates a new tariff version; a pin/hours/parcel change bumps the dispatch-location version; both make open quotes stale (`QUOTE_INVALID` on payment). The area must be one GeoJSON Polygon inside Rwanda; only `STANDARD` parcels are accepted. In a production profile, enabling checkout or live payments returns 409 `PUBLICATION_BLOCKED` while any other release block remains.
